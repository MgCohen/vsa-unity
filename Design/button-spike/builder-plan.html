Button Builder Plan

One JSON entry goes in. One Unity component reads it, checks it and builds a button that matches the HTML button.

PLAN NEEDS YOUR OK

The manifest components.json has one entry, ds-button, in CEM 2.1 shape with a small ds extension. The Unity component DsButton finds its entry, checks it against what it can do, and adds only the parts that the entry names.

An error stops the build and leaves the GameObject as it was. A warning lets the build continue.

Rules of the format · 5 rules
  • Each token has its resolved value. Unity does not resolve var() chains.
  • Each token names one part, one state and one property.
  • Native items have "source": "native". They come from the HTML standard, not from a declaration.
  • Lists are arrays, never maps. JsonUtility cannot read maps.
  • Sprite files are names only. Unity finds them in Art/ next to the manifest.

DsComponent · the base, sketch 
public abstract class DsComponent : MonoBehaviour
{
    [SerializeField] TextAsset manifest;
    [SerializeField] string[] lastResult;   // shown in the Inspector

    protected abstract string Id { get; }
    protected abstract DsCapabilities Capabilities { get; }

    [ContextMenu("Build from manifest")]
    public DsResult Build()
    {
        var entry = DsManifest.Find(manifest, Id);        // E-ID
        var result = Check(entry, Capabilities);          // E-*, W-*
        if (result.HasErrors) return Log(result);         // no change
        foreach (var part in entry.ds.anatomy)
            DsParts.Build(this, part, entry);             // by kind
        OnBuilt(entry);                                   // component-specific
        return Log(result);
    }
}
DsButton · capabilities, sketch 
public sealed class DsButton : DsComponent
{
    [SerializeField] string label = "Play";   // slot text, from screen.json later

    protected override string Id => "ds-button";
    protected override DsCapabilities Capabilities => new()
    {
        Native = "button",
        Attributes = { "disabled" },   // Selectable.interactable
        Events = { "click" },          // Button.onClick
        States = { "normal", "hover", "active", "focus-visible", "disabled" },
        PartKinds = { "image", "label" },
    };

    protected override void OnBuilt(DsEntry entry)
    {
        // DsSelectable: sprite states, label colors, pressed offset.
    }
}
DsParts · one module for each part kind 
static class DsParts
{
    public static void Build(DsComponent owner, DsPart part, DsEntry entry)
    {
        switch (part.kind)
        {
            case "image": Image(owner, part, entry); break;   // Image, sprite, slice
            case "label": Label(owner, part, entry); break;   // child + TMP
        }
    }
    // Each module finds its object or adds it. A second build changes values only.
}

A part with parent: "" goes on the root GameObject. Other parts become a child with the part name.

Build rules

  • A second build finds each object by part name. It changes values and adds nothing twice.
  • The build never deletes a child that it did not make.
  • The runtime reads no JSON. The scene keeps the built components.

Q3 · Property names for computed values FORMAT

CSS moves the face with top: calc(…). The entry calls it child-offset-y, because the face sprite does not move in Unity. The component-data session can decide a general name.

HTML shows hover after a click while the pointer is on the button. The plan uses Normal, and the pointer enter event gives Highlighted again. The touch video shows the result.
