Component Manifest Levels

The data that a complex component needs to go from HTML to Unity, level by level, with wa-button as the test case.

RECOMMENDATION

The manifest entry of each component has 3 levels: API, anatomy and styles. Tokens are a 4th level in one shared file. The styles level holds the cascade result as an ordered list of conditional patches, so Unity never runs a CSS cascade.

Headless Edge (CDP CSS domain) is the cascade reference and the check. It is already on this computer.

Why patches and not a full state table

wa-button has 48,000 state combinations. About 40 patches describe all of them. Unity applies the patches whose condition matches, in list order.

State combinations48,000
Patches~40

5 variants × 5 appearances × 5 sizes × 3 pointer states × 2 focus states × 2⁶ flags (disabled, loading, pill, caret, icon-button, rtl).

Sample files: Design/button-spike/parser/samples/wa-button.manifest.json and ds-button.manifest.json.

L1 · Anatomy · nodes, slots, child components, conditions
Purpose
The node tree that Unity builds: each node has an ID, a part, a slot or a child component, and a render condition.
Source
The render() template, classMap, customStates.set.
Static parser
Anatomy and conditions about 95 %. Parts, slots, children 90 %.
{ "id": "button",
  "element": { "if": "href", "then": "a", "else": "button" },
  "classes": { "loading": "loading", "rtl": "dir:rtl",
               "has-start": "slot:start | withStart",
               "is-icon-button": "isIconButton" },
  "children": [
    { "id": "start",   "slot": "start", "part": "start" },
    { "id": "label",   "slot": "",      "part": "label" },
    { "id": "end",     "slot": "end",   "part": "end" },
    { "id": "caret",   "component": "wa-icon", "part": "caret", "if": "withCaret",
      "props": { "library": "system", "name": "chevron-down" } },
    { "id": "spinner", "component": "wa-spinner", "part": "spinner", "if": "loading" } ] }
"derived": { "isIconButton": "slot: holds only wa-icon" }

Condition grammar: a property name, slot:<name> (the slot has content), dir:rtl, a derived name, | and !. Unity evaluates it.

Link to L2: node IDs, part names and class names are the targets of the style selectors.

L2 · Styles · each rule to a node and a condition
Purpose
The look of each node in each state, with token references and not values.
Source
The 3 sheets in WaButton.css: button, variants, size.
Static parser
Tokens 100 %. Targets and states about 83 %. State coverage about 60 %.

One CSS rule

:host([appearance='accent']) {
  @media (hover: hover) {
    .button:not(.disabled):not(.loading):hover {
      background-color: color-mix(in oklab,
        var(--wa-color-fill-loud, var(--wa-color-neutral-fill-loud)),
        var(--wa-color-mix-hover)); } } }

The same rule as a patch

{ "on": "button",
  "if": { "appearance": "accent", "pointer": "hover",
          "not": ["disabled", "loading"], "media": "hover" },
  "set": { "background-color":
           "mix(oklab, {wa-color-fill-loud}, {wa-color-mix-hover})" } }

Order: the list is in cascade order (layer, then specificity, then source order). A later matching patch wins. Inherited properties (color, font) flow down the anatomy tree.

Link to L3: each {name} is a token name.

L4 · Resolved samples · test fixture from Edge
Purpose
The truth for a sample of states. It checks L2 and L3, and the Unity result.
Source
Edge renders the component. CDP forces each state and reads the computed style and the winning rule.
{ "state": { "variant": "brand", "appearance": "accent", "pointer": "hover" },
  "node": "button",
  "computed": { "background-color": "oklab(0.55 -0.03 -0.2)", "height": "40px" },
  "winner": { "background-color":
    ":host([appearance='accent']) .button:not(.disabled):not(.loading):hover" } }

Check: evaluate the patches and tokens for the same state. The result must equal computed. A difference names the wrong patch.

Child component · caret and spinner · recursion to another entry

The anatomy node gives the component ID and fixed props. Unity uses the prefab of that ID. The child entry gives its own levels.

{ "id": "caret", "component": "wa-icon", "part": "caret", "if": "withCaret",
  "props": { "library": "system", "name": "chevron-down", "variant": "solid" } }

If Unity has no prefab for the ID, the validation gives an error.

Slot · start, label, end · consumer content

A slot is a named container. The consumer puts content in it. Two states come from the content: has-start and is-icon-button.

Unity needs a child RectTransform for each slot and a check that runs when the content changes.

Variant token scope · tokens remap, rules stay the same

The variant does not change a rule. It remaps 9 alias tokens. An ancestor with the class .wa-brand also sets the scope, so the scope is inherited.

Unity needs a token scope component. A component reads a token from the nearest scope, else from the theme.

KEY TOOL

Edge CDP gives the real cascade for each node in each forced state: layers, specificity, shadow scope and the authored var() text. It replaces an own cascade engine as the reference.

Node 26 has a built-in WebSocket, so CDP needs no npm package. record-pointer-cdp.mjs already uses this path.

L0 · @custom-elements-manifest/analyzer · tool gives all
Gives
Attributes with union types, defaults, events, slots, parts, states from TS source and JSDoc.
Own code
None. A plugin adds the ui field.
Other
@lit-labs/analyzer gives the Lit property model and also writes CEM.
Limit
Parts, slots and states come from hand-written JSDoc. The anatomy check of L1 finds JSDoc that does not match the template.
L1 · TypeScript API + parse5 · tool gives the trees, we give meaning
Gives
The class AST: render(), html`` templates, ternaries, classMap. parse5 gives the template HTML tree with markers for the expressions.
Own code
Expressions → condition grammar. Slot content rules (derived). About 150 lines (estimate).
Check
Edge renders a set of prop values and reads the shadow tree. Each node must match an anatomy node.
L2 · PostCSS + Edge CDP · static extract, browser check
Gives
postcss-nested flattens & and nested @media. postcss-selector-parser gives the selector AST. CDP gives the winner for each property.
Own code
Selector AST → node and condition. This is the part with 83 % accuracy, and the AST removes the regex errors.
Why both
Static gives the conditions and token names. The browser gives the truth for one state. A browser alone cannot see conditions.
L3 · PostCSS + DTCG · standard token format
Gives
All custom property declarations of the theme CSS. DTCG is the W3C community format for tokens.
Own code
The alias graph, cycle check, the Unity token asset writer.
Other
Style Dictionary reads DTCG. Add it only if a second output format is necessary.
L4 · Edge CDP sampler · own code, no package
  1. Load the gallery page in headless Edge.
  2. Set the attributes of one state combination.
  3. Force :hover, :active, :focus-visible with CSS.forcePseudoState.
  4. Set hover and prefers-reduced-motion with Emulation.setEmulatedMedia.
  5. Read the computed style and matched rules of each part.

Pairwise sampling covers each pair of axis values in about 40 states, not 48,000.

Q1 · Tool test: install the npm tools in the scratchpad? NEXT

Packages: @custom-elements-manifest/analyzer, typescript, parse5, postcss, postcss-nested, postcss-selector-parser, and @awesome.me/webawesome for the Edge render.

Recommendation: yes. Test L2 first: run PostCSS on the 3 sheets, then compare with CDP for 10 states. The result shows if the 83 % goes to 100 %.

Q2 · Our HTML components: custom elements or CSS classes? DECIDE
OptionForAgainst
A. Lit custom elementsCEM tools give L0. Real slots and parts.Build step, shadow DOM
B. CSS classes on native elementsL0 from the standard. Simple.Variants and slots have no standard declaration

Recommendation: A for components with slots or child components, B for simple ones. Both make the same manifest shape.

Q3 · The extension: a ui field in CEM or a sibling file? DECIDE

Recommendation: a ui field in the declaration. Then one file has all the data. Examine the CEM 2.1 schema for extra fields before the parser writes it.

Q4 · Live tokens or values baked for each state? DECIDE

Live tokens need a small Unity evaluator: token lookup, OKLab mix, calc with px, em and %. Baked values need no evaluator, but a token change needs a build again.

Recommendation: live tokens. It matches Q4 of the UI Parity Plan (option B).

Q5 · Where does behavior data come from? DECIDE

Focus, the click guard and form actions are code, not declarations. A static read finds only known patterns.

Recommendation: take the base behavior from the native root (ui.extends). Extract only the guard disabled | loading. The Unity component implements the rest.

Non-goals

  • No CSS cascade in Unity. Reason: the patch order holds the cascade result.
  • No own cascade engine as the reference. Reason: Edge is exact and already installed.
  • No full state table in the manifest. Reason: 48,000 combinations for one button.
