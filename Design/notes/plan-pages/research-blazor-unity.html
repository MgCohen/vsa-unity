protected override void BuildRenderTree(RenderTreeBuilder b) {
    b.OpenComponent<Label>(0);

    b.CloseComponent();

  • Sequence numbers (0, 1) are static. The diff uses them to match frames.

Rules for a thin component

  • A DS component has no logic. It shows props and raises events.
  • Its parameters are the props of its contract. Its callbacks are the events.
  • It writes data-ui and its props into the HTML.
  • A screen has no logic. It passes presenter state to props and events to presenter methods.
  • All state and all calls go to the presenter.

// Tools/blazor-preview/PresenterView.cs (proposal)
public abstract class PresenterView<T> : ComponentBase, IDisposable where T : Presenter {
    [Inject] protected T Presenter { get; set; }
    protected override void OnInitialized() => Presenter.Changed += OnChanged;
    void OnChanged() => _ = InvokeAsync(StateHasChanged);
    public void Dispose() => Presenter.Changed -= OnChanged;
}

It does in Blazor what PresenterComponent<T> does in Unity: it listens to Changed and renders on the UI thread.

The DS components are few and change slowly, so a hand-made matching set is cheap. Screens are many and change often, so screens use the importer.

Screen text comes from the presenter

A text expression in a screen is logic. Put it in the presenter as a property, for example Summary.

Then the generator copies a property name, not an expression. So a screen has no C# that the generator must translate.

  • How does a list (for example the roll list) map: a data-ui="List" with an item prefab?
