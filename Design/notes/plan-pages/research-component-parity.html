Component Parity

One contract for each component can keep HTML and uGUI in parity, with known gaps in states, focus and layout.

VIABLE contract + prefab parity RISK states, Tab focus, flex layout DEAD END a JS runtime as the Unity path

A design system of about 12 components can have one-to-one parity in uGUI. Most DOM elements and events have a uGUI match, but states, Tab focus and flexbox have gaps. ReactUnity (MIT) shows a tested map that vsa-unity can copy as contracts and prefabs.

// Parity component for contract "Button".
[RequireComponent(typeof(Button))]
public sealed class DsButton : MonoBehaviour {
    [SerializeField] TMP_Text label;
    [SerializeField] Button button;
    public event Action Clicked;

    void Awake() => button.onClick.AddListener(() => Clicked?.Invoke());
    public void SetLabel(string text) => label.text = text;
    public void SetDisabled(bool value) => button.interactable = !value;
}
public sealed class CounterView : PresenterComponent<CounterPresenter> {

}
